================================================================================
ESPECIFICAÇÃO DE ARQUITETURA E REQUISITOS - ONBOARDING DIGITAL (MVP)
================================================================================

1. PROPÓSITO E OBJETIVO DO PROJETO
--------------------------------------------------------------------------------
Este projeto consiste no desenvolvimento do Produto Mínimo Viável (MVP) de uma 
plataforma de "Onboarding Digital" (Admissão Digital de Funcionários). 

O objetivo principal deste repositório é servir como projeto de destaque no 
portfólio do Líder de Projeto no GitHub e LinkedIn, demonstrando competências de:
  - Arquitetura de Software e Modelagem de Negócio.
  - Engenharia Dirigida por IA (AI-Assisted Engineering).
  - Conformidade Legal e Segurança Jurídica (LGPD e Trilha de Auditoria).
  - Acessibilidade Web (ESG / VLibras).
  - Prontidão para integração via API REST (Arquitetura B2B).

2. PAPÉIS E RESPONSABILIDADES NO DESENVOLVIMENTO
--------------------------------------------------------------------------------
- LÍDER DE PROJETO E ARQUITETO DE NEGÓCIOS (Usuário / Vítor):
  Responsável pela direção estratégica, validação das regras de negócio, 
  aprovação dos blocos de código, controle do escopo e criação das telas / design.

- ARQUITETO SÊNIOR E CONSULTOR DE ENGENHARIA (Gemini):
  Responsável pela especificação técnica detalhada, estruturação das regras de 
  negócio, criação das linhas de comando e explicação lógica linha por linha do código.

- AGENTE EXECUTOR DE CÓDIGO (Claude Code):
  Responsável pela execução precisa das instruções de código e comandos de terminal 
  fornecidos, mantendo o código limpo, comentado e estruturado conforme o especificado.

3. TECH STACK (LINGUAGENS E TECNOLOGIAS UTILIZADAS)
--------------------------------------------------------------------------------
- LINGUAGEM PRINCIPAL: JavaScript (ES6+)
  MOTIVO DA ESCOLHA: Padronização da linguagem em toda a stack (Full-Stack 
  JavaScript), permitindo alta performance, ecossistema maduro para APIs e 
  fácil integração entre Frontend e Backend.

- BACKEND (SERVIDOR & API): Node.js + Express.js
  MOTIVO DA ESCOLHA: O Node.js oferece uma arquitetura orientada a eventos leve e 
  eficiente. O Express.js é o framework padrão para criação de APIs RESTful limpas 
  e prontas para integrações B2B.

- FRONTEND (INTERFACE DE USUÁRIO): HTML5 + CSS3 + JavaScript puro (Vanilla JS)
  MOTIVO DA ESCOLHA: Garante que a aplicação seja extremamente rápida, sem a 
  complexidade desnecessária de frameworks pesados no MVP, facilitando a leitorabilidade 
  do código para recrutadores.

- VERSIONAMENTO: Git e GitHub
  MOTIVO DA ESCOLHA: Manutenção de um histórico claro de commits para apresentação 
  profissional do repositório.

4. REQUISITOS DE NEGÓCIO E FUNCIONALIDADES DO MVP
--------------------------------------------------------------------------------
A) FICHA ÚNICA DO CANDIDATO:
   Formulário de entrada para captura dos dados obrigatórios de admissão:
   - Nome Completo
   - Data de Nascimento
   - CPF
   - Endereço Residencial (Logradouro, Número, Bairro, Cidade, UF)
   - CEP
   - Número da Carteira de Trabalho (CTPS Digital / Física)
   - E-mail de Contato
   - Telefone / WhatsApp de Contato

B) MATRIZ DE MATURIDADE E CONTROLE DE STATUS (SISTEMA DE CORES):
   O status do processo admissional é sinalizado visualmente por um sistema de cores 
   para garantir fácil leitura de pendências pelo time de RH:
   - VERMELHO (#DC3545): Pendente / Não Iniciado.
     Indica que o candidato ainda não preencheu os dados essenciais ou faltam 
     documentos obrigatórios.
   - AMARELO (#FFC107): Em Análise / Processamento.
     Indica que a ficha foi submetida e os dados/documentos foram recebidos, 
     aguardando validação do setor de RH.
   - VERDE (#28A745): Aprovado / Concluído.
     Indica que a validação foi realizada com sucesso e a admissão está apta a prosseguir.

C) TRILHA DE AUDITORIA & CONFORMIDADE LGPD:
   O sistema deve registrar logs imutáveis para cada aceite ou alteração realizada:
   - Captura do endereço IP do candidato.
   - Registro de Data e Hora exata (Timestamp).
   - Armazenamento da declaração de consentimento de uso de dados pessoais.

D) ACESSIBILIDADE E COMPLIANCE:
   - Estruturação HTML semântica para leitores de tela.
   - Suporte para integração de ferramentas de acessibilidade em Libras (ex: VLibras).

5. REGRAS DE EXECUÇÃO DE CÓDIGO PARA O CLAUDE CODE
--------------------------------------------------------------------------------
- As alterações de código devem ser feitas estritamente via linhas de código explícitas 
  fornecidas pelo Líder de Projeto.
- Os arquivos devem ser organizados seguindo a estrutura de diretórios do projeto:
    /public (arquivos estáticos HTML/CSS/JS)
    index.js (servidor Node.js)
    package.json (dependências)
- Manter comentários descritivos no código em português.
